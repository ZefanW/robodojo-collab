# Frozen algorithm and comparison boundaries

`astra-l3-persistent-cap20` implements GPT-6 Astra medium through Codex0.153.4 and the frozen RoboProbe9ffacc54 L3 EEF interface. Native recipes, task scoring and motion planning remain upstream. The original motion path is retimed first, then only its first20 control commands execute; the suffix is discarded. Actual gripper latching follows the last executed command, and arrival error stays relative to the original target. The next native observation closes the loop. Short paths are unchanged. This is an action prefix, not an extra20-step simulation budget.

One native thread holds the episode's dialogue, original observations and opaque reasoning. Automatic native compaction is allowed and recorded; full private disk history remains. The JSON assistant/tool envelope is a Codex transport adaptation, not a claim of byte-identical public Responses API function calls. Unexpected host instructions or tool output stop the run. Codex can attempt a disabled host tool, adding model responses and cost; all responses must remain accounted for. Server-side model weights are not frozen by the alias.

Recipes are a material part of the condition. They include operational/scoring advice. `imitate_sorting_sequence` includes the upstream600-control demonstration-observation phase before model decisions; report that separately from paid decisions and compare matched conditions. No result should attribute a difference solely to history when client, simulator, recipe or source differs.

The scene key is `(task, official_seed, layout_ordinal, asset_sha256)`. Official directory names are0/1/2; the catalog records numeric file order independently from seed. A repeated execution of the same SHA is another attempt, not a new geometry. Baseline0/0 and later0/1 panels are separate. At later ordinals, unavailable tasks are structural absence, not failures. Record round index and attempt lineage explicitly. Random-task names are part of the task configuration, not synonyms for official seed.

The exact current baseline simulator mapping is in `registry/simulator-mapping.json`. Full comparisons require matching per-task simulator family and disclose all environment differences. The portable source adaptation is separately versioned and CPU tested; a prepared native source lock is not proof it reproduces the historical GPU environment. Every fresh contributor must retain observed driver/GPU/dependency versions and source hashes, then verify native evidence.

A valid terminal requires a real native result with matching `episode_complete`, matching control counts and no unresolved invalid initialization. Queued, initializing, process-exited and partial-transcript states are not valid terminals. Native zero scores remain zero. Incomplete and structurally missing cases remain missing. All paid attempts count even if no valid terminal exists. Response mirrors are not additional attempts; cache is included in input; unknown usage stays unknown.

Use five capabilities with equal weight for a complete official scope. Within Generalization, standard/random receive equal half weights; do not simply average all54 configurations. Declare the task panel before evaluating. Show per-task count, mean, sample standard deviation and range over actual geometry attempts; sample SD is undefined for n<2. Keep per-panel outcomes and across-panel task means separate. Do not select the best attempt, overwrite failures, or report a partial panel as a full benchmark total. The imported historical datasets may have differing task/environment scope and must remain labeled.

License/source provenance is in `registry/source-lock.json`, `licenses/`, and [ENVIRONMENT.md](ENVIRONMENT.md). Assets/checkpoints stay with their original providers. Publishing code and a result index is not an official RoboDojo leaderboard submission.
