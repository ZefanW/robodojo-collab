# Contribute one scene without a central scheduler

Before repairing a failed start or interruption, consult [Chinese errata E11–E19](ERRATA_zh-CN.md#allocation). It separates claim/initialization failures, already-paid reply delivery, generation failures and file-only archive repairs; each needs different evidence before continuation.

Start with the CPU example contribution and validation commands in the main README. They require no Codex login, GPU, or quota. Real execution is a separate opt-in operation, and the portable runner has not yet been exercised on a fresh third-party GPU/account. Read [ENVIRONMENT.md](ENVIRONMENT.md) for machine setup and [QUOTA.md](QUOTA.md) for the first-login/passive-notification limitation before starting a scene.

Commands below run from the collaboration repository root. `controller` means the host with your own Codex login; `simulator` means the Linux RTX host. They may be the same machine. Keep the run ID, package and original state across every later command; do not restart this guide from step 1 after a connection failure.

## 1. Allocate, identify, configure

Choose a task/seed/layout from `registry/scenes.json`. `seed` is an actual official directory (0,1,2); layout is the numeric-file ordinal within that task and directory. Create a **new** run ID for each explicitly intended attempt. Use a public contributor pseudonym. Request/accept the shared GitHub assignment or shared lease before a paid call; a local clone's lock cannot coordinate other clones.

```sh
mkdir -p .private
cp configs/contributor.example.json .private/contributor.json
python scripts/make_package.py --task stack_bowls --seed 0 --layout 1 --run-id YOUR_UNIQUE_RUN_ID --contributor YOUR_PUBLIC_ID --output .private/task.json
```

Replace the uppercase values before running. The example task uses Sim6. The default `--attempt` is **0**, the first intended attempt for that exact scene. A separate explicitly approved repeat requires `--attempt 1 --repeats-run-id ORIGINAL_RUN_ID --reason 'ACTUAL_REASON'` and another allocation; do not use this to escape a failed or interrupted attempt. `make_package` refuses to overwrite its output. Existing package after a disconnect means continue with it, not generate a new ID.

Read the selected family and package identity without starting anything:

```sh
python - <<'PY'
import json
from pathlib import Path
p = json.loads(Path('.private/task.json').read_text())
families = json.loads(Path('registry/simulator-mapping.json').read_text())['tasks']
print(json.dumps({'run_id':p['run_id'], 'work_id':p['work_id'],
                 'scene':p['scene'], 'simulator_family':families[p['scene']['task']]}, indent=2))
PY
```

Fill your own absolute paths, SSH alias, selected GPU/port, own login directory and pinned executable SHA. Driver/GPU model metadata is measured automatically; do not invent it in the config. Prepare `.private/simulator.json` on the simulator using its actual paths, and put the JSON object generated by `prepare_native` into its `simulator.native_source_sha256`. In one-host mode you may use `.private/contributor.json` for both commands; replace the simulator-config arguments below accordingly. For SSH the invariant is **controller `transport.root` = simulator `simulator.output_root`**. See the machine/path table in [ENVIRONMENT.md](ENVIRONMENT.md#choose-one-or-two-machines-first).

Copy only `.private/task.json` to the simulator and verify its file SHA on both hosts; do not regenerate it there. A standard-library check is `python -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('.private/task.json').read_bytes()).hexdigest())"`. This file-byte check is distinct from the runner's canonical JSON package hash.

Use the `work_id` stored in the task package with the commands in [CLAIMS.md](CLAIMS.md). The authoritative `work-claims` branch must already exist. Direct writers use non-force Git compare-and-swap pushes; other contributors submit a prebound reservation PR and wait for the accepted upstream record. Keep the original private token at `claim.token_file` on each participating host. The runner checks owner/token hash, exact run and execution instance, and an unexpired lease. An identical prebinding is a read-only no-op; a different run/instance fails. It rechecks remote state at least every 60 seconds and local expiry at each boundary. A local clone assertion or `accepted-assignment.example.json` is not executable allocation authority.

Set your **own** reserve percentage and credit policy explicitly. An example's null reserve deliberately blocks. Complete [QUOTA.md](QUOTA.md): obtain already trusted, fresh, account-bound native passive evidence; preserve the actual observation time; validate it through the guard. Login alone does not generate that snapshot, and missing identity in ongoing native events is a documented compatibility hold. Do not start the GPU while this prerequisite is unresolved. No quota RPC, account switch, credential sharing, credit purchase, or API fallback is implemented.

## 2. Check, then start the native scene

```sh
python -m robodojo_collab.runner check --config .private/contributor.json --package .private/task.json
```

Expected output is `package_valid:true`, `sources_valid:true`, `paid_calls:0`. This command checks the package contract and controller source lock only; it does **not** validate login, quota, SSH access, claim, assets, GPU, or native environment. Review both doctor reports and the prerequisites above separately.

Set `execution_authorized=true` in the configs you will actually use only after allocation and your budget decision. Set `simulator.license_accepted=true` only after accepting the applicable NVIDIA/upstream terms. On the **simulator host**, this repository copy needs the contributor's Git/shared claim access but no Codex auth file. Compute the native binding before a reservation PR or startup:

```sh
python -m robodojo_collab.runner binding-info --config .private/simulator.json --package .private/task.json
# Only after this exact upstream allocation/binding is accepted:
python -m robodojo_collab.runner native-start --config .private/simulator.json --package .private/task.json
```

The first native launch binds the claim to the machine pseudonym, resolved output root and run ID. It launches one policy server and one native simulator in their own process groups, records exact commands/PIDs, and returns `launched_not_yet_native_action`. This is startup, not an action or result. The source and selected asset SHA must match; no heartbeat or unrelated process is started/stopped. Choose a free GPU/port and retain sufficient headroom. Separate run processes can still race for physical resources: this small runner is not a host-wide GPU/RAM scheduler. Allocate resources before launching, and do not start several copies merely because their claims differ.

On the controller, inspect the same original scene:

```sh
python -m robodojo_collab.runner status --config .private/contributor.json --package .private/task.json
```

Before the first paid boundary, both `owned_processes_alive.server` and `.simulator` must be true and `pending` must describe the original run's request (normally index 0). The original three observation images arrive in that mailbox request. Inspect their real content before trusting rendering; neither process liveness nor a generated placeholder proves camera validity. If `pending` is null, initialization may still be running; inspect the original `<simulator.output_root>/<RUN_ID>/server.log` and `simulator.log` on that host. Do not call a paid model to diagnose startup. Status includes private paths and is not a public artifact.

If startup fails, preserve the output directory and logs. `native-start` refuses an existing run directory even after a zero-paid failure. Do not delete that directory, select a fresh run ID, reset the scene, or invoke preparation again as a repair shortcut. A maintainer must reconcile the exact failure before any explicitly authorized corrective launch.

## 3. Run the controller on your own account

Refresh from newer **real** passive evidence if the bootstrap aged during native initialization. On the controller, after the first pending request and all prerequisites are verified, run the first authorized decision boundary:

```sh
python -m robodojo_collab.runner start --once --config .private/contributor.json --package .private/task.json
```

`--once` handles at most one pending mailbox decision, then returns; if there is no request it can return without any decision. It is **not** a guarantee of one billable model response: native compaction or internal service behavior can produce multiple recorded response receipts within a decision. Do not treat it as a fixed token/dollar budget. A saved `calls/0000/response.json` plus `delivered.json` proves saved/delivered output; native action/feedback evidence and the next observation prove execution. Inspect `session/rpc_out.jsonl` for the original quota notification and any `context-hold.json` before authorizing further continuation. A missing-account notification or stale allowance remains a hold even if the first physical action completed.

Once the original first boundary is reconciled, allowance remains known, and ongoing notification compatibility has been established for your client/account, continue the **same** scene/session:

```sh
python -m robodojo_collab.runner resume --config .private/contributor.json --package .private/task.json
```

`resume` stays in the foreground until native result, pause, or hold. Run `status` from a second terminal with the same activated controller environment. Keep this controller process and its original state directory alive; network interruption is not permission to run `start` again.

Each native request is immutable and hash bound. The controller uses the original system/tool hashes, exact Astra medium, and one persistent native session. Full images and original opaque reasoning stay in private local session files; they are not public rationale. The original action policy performs validation, native motion planning/retiming and at most the first 20 controls; no queued suffix executes later. It caps model decisions at100 independently of native episode control budgets. The runner currently handles one scene at a time; intentionally keeping it small avoids accidental paid concurrency across contributors.

To pause, create `<controller.state_root>/<RUN_ID>/pause.request` from a second terminal. It stops new calls at a boundary and leaves native processes waiting; an in-flight paid boundary may still finish and deliver its saved reply. Do not kill/reset the simulator. Ctrl-C retains native processes but can interrupt the model/history boundary and require manual reconciliation, so the pause marker is preferred. Before resuming, verify the live scene, claim/allowance and original receipts, then remove your own pause marker deliberately. Never erase history, owner identity or `paid-start.json` to clear a hold.

## 4. Recover a connection without repeating paid calls

```sh
python -m robodojo_collab.runner reconcile --config .private/contributor.json --package .private/task.json
python -m robodojo_collab.runner resume --config .private/contributor.json --package .private/task.json
```

First prove that the original controller process has stopped; do not run standalone `reconcile` alongside it. `reconcile` is **not read-only**: it compares saved local/remote receipts and may deliver an existing paid reply, causing robot actions. It makes no new model call. Standalone reconciliation checks native/claim/controller ownership but does not itself run the quota guard; `resume` checks fresh allowance before paid progression. Delivery is idempotent and never overwrites a different response.

Resume requires the original journal, preserved history, matching next boundary and an idle original native thread. It does not inject history again, create a replacement thread, reset a scene or repeat controls. Original native processes must still be alive unless the native result already exists. An unresolved paid attempt, interrupted history commit, missing journal, or uncertain receipt is a manual hold. If `--once` returned before any call, inspect the saved session state first; do not assume a new `start` is harmless. This initial portable release implements **zero automatic paid retries**; the historical maximum-two repair mechanism is retained as source evidence but is not enabled for another contributor.

The local lock prevents concurrent controller owners on one machine. The Git/shared claim prevents another run from binding to the same work item, and the native mailbox binds to the originating controller state. It cannot prevent a malicious contributor from ignoring the protocol. Expired shared leases need reconciliation; no automatic takeover occurs.

## 5. Validate/export/upload/index

A native result file only triggers collection; it does not certify completion. Compare `_result.json`, the native `episode_complete` event, action ACK counts, control steps, transcript end state, and `unstable_envs`. Preserve zero-score and failed attempts. Collect the immutable native archive first, then use the portable public exporter:

```sh
python -m robodojo_collab.runner collect --config .private/contributor.json --package .private/task.json --destination .private/collected
python -m robodojo_collab.export_new --controller .private/controller/RUN_ID --native .private/collected/RUN_ID --package .private/task.json --destination staging/my-contribution --tar
```

Collection supports a local simulator directory or SSH+rsync (rsync3 with `--protect-args`); it verifies the source file manifest both before and after copying and hashes every local file. Then use the repository's result-schema/import and artifact-upload workflow in the README. Public bundles should include the three native camera videos, three-view public-note demo when actually present, original images, action/feedback timeline, native evidence, per-file SHA, all-attempt cost and sanitized environment provenance. Unknown token usage is null with a reason, never zero; cached tokens are an input subset.

Replace `RUN_ID` with the package's original run ID, and replace `.private/controller` if you configured another `controller.state_root`. The collection directory is a parent: the collector adds `/RUN_ID` itself. Expected output reports `verified_files`; the exporter then checks the immutable collection proof and terminal evidence. If copying fails, retry **collection** after inspecting the existing files; do not rerun the model or simulator to repair an archive. A hash collision or changing native archive needs reconciliation, not deletion. Keep the original controller state and native archive after publishing.

The runner does not upload raw sessions or its `.private` directory. Public audit copies include native inputs, tool calls, public assistant note/reason and feedback only. Private reasoning, auth paths, account IDs, credentials and host paths must be excluded by the exporter. Do not invent public rationale where none was emitted. A storage upload is finished only after readback SHA verification; a cloud landing page is not a video playback URL.

```sh
python -m unittest discover -s tests -v
ROBODOJO_TEST_ROBOPROBE="$(pwd)/vendor/RoboProbe" python -m unittest discover -s tests -p test_cap20_frozen_cpu.py -v
python scripts/test_offline_wire.py --codex /path/to/pinned/codex --roboprobe vendor/RoboProbe --output .private/offline-wire
```

The last test points the pinned client only at a localhost synthetic provider with no OpenAI authentication. It tests three incremental turns, a process restart and original-thread resume, retained images/history, and response accounting without paid inference. Use a new output folder each time; the helper refuses to overwrite evidence. This is transport verification, not a score or GPU task. Public release evidence is in `docs/PORTABLE_VALIDATION.json`.
